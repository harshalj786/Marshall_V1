# of this file is that the next dependency change is a deliberate, reviewable diff

# direct-imports-only list would not have prevented it. Everything else (torch,
# numpy, transformers, ...) is left to resolve normally — see the notes at the
# bottom. For a byte-exact snapshot of this machine, use `pip freeze`; this file
# is meant to stay readable.

# ==============================================================================
# NOTES
# ==============================================================================
#
# 1. torch is deliberately NOT pinned here.
#    The working machine runs torch==2.6.0+cu124, a CUDA build. That `+cu124`
#    local version identifier does not exist on PyPI, so pinning it would make
#    `pip install -r requirements.txt` fail outright; and pinning plain
#    `torch==2.6.0` would resolve to the CPU wheel and silently replace a working
#    GPU install. torch arrives transitively via sentence-transformers, so leaving
#    it unpinned is the only option that is safe in both directions.
#
#    To reproduce the GPU environment (RTX 4080 per docs/archive/tech_stack_v2_dead.md):
#        pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
#
# 2. pdfplumber was missing when this file was first written, which made
#    mode_docs="scanned_pdf" raise ImportError at load() despite README.md:280
#    advertising it. Now installed and pinned, and the mode is verified working.
#    It pulls in pdfminer.six, pypdfium2, Pillow and cryptography transitively;
#    those are left unpinned like the rest of the non-langchain surface.
#
# 3. duckduckgo-search is NOT listed even though it is installed (8.1.1) and
#    README.md:83 tells you to install it. The current langchain-community does
#    `from ddgs import DDGS` — the renamed package — so duckduckgo-search is
#    vestigial and unused. Pinning it would freeze dead surface area.
#
# 4. python-dotenv is not listed: .env exists with four keys but no module in the
#    repository reads it (no dotenv / os.environ / os.getenv import anywhere).
#    Add it when configuration is actually wired up — see R2 in
#    docs/architecture_review.md.
#
# 5. espeak-ng is NOT a system dependency here, despite every Kokoro install guide
#    saying it is. `espeakng-loader` ships the DLL and the language data inside the
#    wheel, and `phonemizer-fork` loads them from there, so `pip install -r
#    requirements.txt` is the whole install on Windows — no MSI, no PATH entry, no
#    admin prompt. Verified: KPipeline(lang_code="a") synthesises with no
#    espeak-ng.exe anywhere on the machine. This is why the piper-tts fallback
#    contemplated for V1a was never needed and is not listed.
#
# 6. misaki downloads spacy's `en_core_web_sm` (12.8 MB) on FIRST USE, by shelling
#    out to pip against a GitHub release URL. It is therefore not pinnable here in
#    any honest way — it is not on PyPI — and the first Kokoro call on a fresh
#    machine needs network even though every listed package is already installed.
#    `voice_main.py --check` triggers it deliberately, so that download happens
#    during setup rather than in the middle of the first spoken answer.
#
# 7. faster-whisper on CUDA needs cuDNN 9 for CTranslate2, which is NOT pip-installed
#    here — it is already present on this machine via the torch cu124 install (note 1).
#    A machine with CPU-only torch will fail CTranslate2's CUDA init; voice/stt.py
#    catches exactly that and falls back to device="cpu", compute_type="int8" with a
#    logged warning rather than dying. Verified working as
#    device="cuda", compute_type="int8_float16".
